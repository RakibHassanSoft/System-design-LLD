# Git Merge Conflict

A **merge conflict** happens in Git when two branches modify the same part of a file differently, and Git cannot decide which change should be kept.

---

# Simple Example

Suppose we have this code:

```java
String name = "Rakib";
```

Now we create two branches.

### Branch 1

Developer A changes it to:

```java
String name = "Rakib Hassan";
```

### Branch 2

Developer B changes the same line to:

```java
String name = "Rahim";
```

Now we try to merge **Branch 2 into Branch 1**.

Git doesn't know:

```text
Should I use "Rakib Hassan"
              OR
Should I use "Rahim"?
```

So Git creates a **merge conflict**.

---

# What a Merge Conflict Looks Like

Git may mark the conflict like this:

```text
<<<<<<< HEAD
String name = "Rakib Hassan";
=======
String name = "Rahim";
>>>>>>> branch2
```

---

# What Do These Symbols Mean?

### `<<<<<<< HEAD`

Means:

> The version from your **current branch**.

```text
<<<<<<< HEAD
String name = "Rakib Hassan";
```

---

### `=======`

Separates the two different versions.

```text
String name = "Rakib Hassan";
=======
String name = "Rahim";
```

---

### `>>>>>>> branch2`

Means:

> The version coming from the **other branch**.

```text
=======
String name = "Rahim";
>>>>>>> branch2
```

---

# How to Solve a Merge Conflict

You must manually decide which change should be kept.

For example, if you want:

```java
String name = "Rakib Hassan";
```

Delete the conflict markers and the unwanted version.

The final code should be:

```java
String name = "Rakib Hassan";
```

Then stage and commit the resolved file:

```bash
git add .
git commit -m "Resolve merge conflict"
```

---

# Merge Conflict Resolution Flow

```text
Merge branches
      ↓
Git detects conflict
      ↓
Open the conflicted file
      ↓
Check both versions
      ↓
Choose the correct change
      ↓
Delete conflict markers
      ↓
Save the file
      ↓
git add .
      ↓
git commit -m "Resolve merge conflict"
      ↓
Conflict resolved ✅
```

# Real-Life Example

Imagine two students are working on the same project.

### Student A

Changes:

```text
Login button → Blue
```

### Student B

Changes:

```text
Login button → Red
```

Both students changed the **same property differently**.

Git cannot automatically decide whether the button should be:

```text
Blue
  OR
Red
```

Therefore, Git creates a **merge conflict**.

The developer must decide which change should be kept.

---

# Easy Definition for Exam

> **A merge conflict occurs when Git cannot automatically merge two branches because they contain different changes in the same part of a file. The developer must manually choose and resolve the correct changes.**

---

# Quick Memory Guide

```text
Two branches
     ↓
Same code changed
     ↓
Different changes
     ↓
Git confused ❌
     ↓
Merge Conflict
     ↓
Developer resolves it ✅
```

# Important Git Commands

| Command      | Purpose                           |
| ------------ | --------------------------------- |
| `git status` | Check which files have conflicts  |
| `git add .`  | Mark the conflict as resolved     |
| `git commit` | Save the resolved merge           |
| `git diff`   | View changes and conflict details |
