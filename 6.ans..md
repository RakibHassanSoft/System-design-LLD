# Web Application Architecture

A modern web application is mainly divided into **three important parts**:

```text
Frontend
Backend
Database
```

These three parts work together to create a complete web application.

A simple way to remember them is:

```text
User
 ↓
Frontend
 ↓
Backend / API
 ↓
Database
```

For example, when a user logs into a website:

```text
User enters email + password
          ↓
       Frontend
          ↓
       Backend
          ↓
       Database
          ↓
       Backend
          ↓
       Frontend
          ↓
    User sees dashboard
```

---

# 1. Frontend

The **frontend** is the part of a web application that users can see and interact with.

It includes things such as:

* Buttons
* Forms
* Menus
* Images
* Text
* Navigation bars
* Dashboards
* Login pages
* Product pages
* Tables
* Cards

The frontend usually runs inside the user's **web browser**.

Examples of frontend technologies include:

```text
HTML
CSS
JavaScript
TypeScript
React
Next.js
Vue.js
```

---

## What Does the Frontend Do?

The frontend is responsible for:

1. Displaying information to the user.
2. Collecting information from the user.
3. Handling user interactions.
4. Sending requests to the backend.
5. Receiving responses from the backend.
6. Updating the screen based on the response.

For example, imagine a login page:

```text
+--------------------------------+
|          Login                 |
|                                |
| Email:    [______________]     |
|                                |
| Password: [______________]     |
|                                |
|          [ Login ]              |
+--------------------------------+
```

The user enters:

```text
Email:    rakib@gmail.com
Password: 123456
```

Then clicks:

```text
[ Login ]
```

The frontend collects this information and sends it to the backend.

---

# 2. Backend

The **backend** is the server-side part of the application.

Users normally don't directly see the backend.

The backend receives requests from the frontend, processes them, applies business rules, communicates with the database, and sends a response back.

Common backend technologies include:

```text
Node.js
Express.js
NestJS

Python
Django
FastAPI

Java
Spring Boot

C#
ASP.NET
```

---

## What Does the Backend Do?

The backend is responsible for things such as:

* Processing requests
* Business logic
* Authentication
* Authorization
* Validation
* Security
* Communicating with databases
* Creating API responses
* Processing payments
* Managing users
* Handling orders

For example, when the frontend sends:

```text
POST /api/login
```

the backend receives the request.

It might receive JSON like:

```json
{
  "email": "rakib@gmail.com",
  "password": "123456"
}
```

The backend then processes this information.

---

# 3. API

An **API** is a communication interface that allows the frontend and backend to communicate.

A common architecture is:

```text
Frontend
    ↓
   API
    ↓
Backend
```

The frontend doesn't normally call the backend's internal functions directly.

Instead, it sends an HTTP/HTTPS request to an API endpoint.

For example:

```text
POST /api/login
```

The API can be designed using approaches such as:

```text
REST API
GraphQL
```

Data is commonly exchanged using:

```text
JSON
```

---

# 4. HTTP Request

When the frontend communicates with the backend, it commonly uses **HTTP or HTTPS**.

For example:

```text
POST /api/login
```

Here:

```text
POST
```

is the HTTP method.

```text
/api/login
```

is the API endpoint.

The frontend might send:

```json
{
  "email": "rakib@gmail.com",
  "password": "123456"
}
```

The backend processes it and may return:

```json
{
  "message": "Login successful"
}
```

---

# 5. Common HTTP Methods

Some common HTTP methods are:

| Method   | Common Purpose        |
| -------- | --------------------- |
| `GET`    | Retrieve data         |
| `POST`   | Create/send data      |
| `PUT`    | Replace/update data   |
| `PATCH`  | Partially update data |
| `DELETE` | Delete data           |

For example:

```text
GET    /api/users
POST   /api/users
PATCH  /api/users/10
DELETE /api/users/10
```

These are examples of API endpoints.

---

# 6. Database

The **database** stores and manages the application's data.

For example, an application might store:

```text
Users
Products
Orders
Messages
Payments
Comments
Posts
```

Common databases include:

```text
PostgreSQL
MySQL
MongoDB
SQL Server
```

---

# 7. Example Database

Suppose our application has a `users` table.

It might contain:

| id | name  | email                                     |
| -: | ----- | ----------------------------------------- |
|  1 | Rakib | [rakib@gmail.com](mailto:rakib@gmail.com) |
|  2 | John  | [john@gmail.com](mailto:john@gmail.com)   |
|  3 | Alex  | [alex@gmail.com](mailto:alex@gmail.com)   |

When the backend needs information about a user, it can query the database.

For example:

```sql
SELECT * FROM users
WHERE email = 'rakib@gmail.com';
```

The database searches the data and returns the matching user.

---

# 8. ORM

The backend can communicate with a database using database queries.

It can also use an **ORM (Object-Relational Mapper)**.

Examples include:

```text
Prisma
Sequelize
TypeORM
```

An ORM allows developers to work with database data using programming-language objects and methods instead of writing every SQL query manually.

For example, conceptually:

```text
Backend
   ↓
ORM
   ↓
Database
```

The ORM handles much of the interaction with the database.

---

# 9. Why Doesn't the Frontend Directly Access the Database?

Normally, the frontend should **not directly communicate with the database**.

Instead:

```text
Frontend
    ↓
 Backend
    ↓
Database
```

The backend acts as a secure middle layer.

If the frontend directly accessed the database, sensitive information such as database credentials or unrestricted database access could potentially be exposed.

The backend can instead:

* Validate requests
* Check authentication
* Check permissions
* Apply business rules
* Control which data can be accessed
* Hide database credentials
* Return only the required information

# 10. Beginner Example — Login System

Let's understand the complete process using a simple login system.

Imagine we have a website called:

```text
MyWebsite
```

The login page contains:

```text
+--------------------------------+
|            LOGIN               |
|                                |
| Email:    [______________]     |
|                                |
| Password: [______________]     |
|                                |
|          [ LOGIN ]              |
+--------------------------------+
```

The user enters:

```text
Email:
rakib@gmail.com

Password:
mypassword
```

---

## Step 1 — User

The user enters their information and clicks:

```text
[ LOGIN ]
```

The process begins:

```text
User
 ↓
Login button
```

---

## Step 2 — Frontend

The frontend receives the values from the form.

Conceptually:

```text
Email = "rakib@gmail.com"
Password = "mypassword"
```

The frontend then prepares a request for the backend.

---

## Step 3 — API Request

The frontend sends an HTTP request:

```http
POST /api/login
```

with JSON:

```json
{
  "email": "rakib@gmail.com",
  "password": "mypassword"
}
```

So now:

```text
Frontend
    ↓
POST /api/login
    ↓
Backend
```

---

# 11. Step 4 — Backend Receives the Request

The backend receives:

```json
{
  "email": "rakib@gmail.com",
  "password": "mypassword"
}
```

The backend first validates the request.

For example:

```text
Is email provided?
        ↓
      YES

Is password provided?
        ↓
      YES
```

Then it needs to find the user.

---

# 12. Step 5 — Backend Asks Database

The backend asks the database to find the user.

Conceptually:

```sql
SELECT *
FROM users
WHERE email = 'rakib@gmail.com';
```

The database searches its users table.

For example:

```text
users table

ID     Email
-------------------------
1      rakib@gmail.com
2      john@gmail.com
3      alex@gmail.com
```

The database finds:

```text
rakib@gmail.com
```

and returns the relevant user information to the backend.

---

# 13. Step 6 — Backend Checks the Password

The backend now verifies whether the submitted password is correct.

In a real application, passwords should **not be stored as plain text**.

Instead, passwords are normally stored using secure password hashing.

Conceptually:

```text
Submitted password
        ↓
Backend verifies it
        ↓
Stored password hash
        ↓
Match?
```

If the credentials are valid:

```text
Login = SUCCESS
```

If they are invalid:

```text
Login = FAILED
```

---

# 14. Step 7 — Backend Creates Authentication

If the login is successful, the backend can establish authentication.

Common approaches include:

```text
Session
JWT / access token
```

For example:

```text
Login successful
       ↓
Create authentication information
       ↓
Send response to frontend
```

---

# 15. Step 8 — Backend Sends Response

The backend sends a response to the frontend.

For example:

```json
{
  "message": "Login successful"
}
```

Or, depending on the authentication design, it may also return authentication-related information.

The communication is now:

```text
Database
    ↓
Backend
    ↓
API
    ↓
Frontend
```

---

# 16. Step 9 — Frontend Updates the Screen

The frontend receives the response.

If login succeeds:

```text
Login successful
       ↓
Open Dashboard
```

The user may now see:

```text
+--------------------------------+
|        Welcome, Rakib          |
|                                |
|        Dashboard               |
|                                |
|  Profile   Orders   Settings   |
+--------------------------------+
```

---

# 17. Complete Login Flow

The complete process is:

```text
User
  ↓

  ↓
API Request
  ↓
Backend
  ↓
Database
  ↓
Backend
  ↓

  ↓
```

Or, in one line:


# 18. Very Simple Real-Life Analogy

Think of a restaurant.

```text
Customer
    ↓
Waiter
    ↓
Kitchen
    ↓
Food Storage
```

The customer doesn't normally enter the kitchen or food storage.

Instead:

```text
Customer
   ↓
Waiter
   ↓
Kitchen
   ↓
Food Storage
```

Then the response comes back:

```text
Food Storage
   ↓
Kitchen
   ↓
Waiter
   ↓
Customer
```

A web application works similarly.

```text
User
   ↓
Frontend
   ↓
Backend
   ↓
Database
```

Here:

```text
User      = Customer
Frontend  = Waiter
Backend   = Kitchen
Database  = Food Storage
```

This analogy helps beginners understand why the frontend normally does not directly access the database.

# 21. Important Terms

| Term               | Simple Meaning                                        |
| ------------------ | ----------------------------------------------------- |
| **Frontend**       | What the user sees and interacts with                 |
| **Backend**        | Server-side logic that processes requests             |
| **API**            | Communication interface between systems               |
| **HTTP**           | Protocol commonly used for web communication          |
| **JSON**           | Common format for exchanging data                     |
| **Database**       | Stores application data                               |
| **ORM**            | Tool that helps backend code interact with a database |
| **Authentication** | Determines who the user is                            |
| **Authorization**  | Determines what the user is allowed to do             |
| **Business Logic** | Rules that control how the application works          |

---

# 22. Authentication vs Authorization

These two terms are often confused.

### Authentication

**Who are you?**

Example:

```text
Email + Password
       ↓
Are you really Rakib?
```

### Authorization

**What are you allowed to do?**

Example:

```text
Rakib is logged in
       ↓
Is Rakib allowed to delete this account?
```

So:

```text
Authentication → Who are you?

Authorization → What can you do?
```

Imagine an online shopping website.

The user sees:

```text

Price: $800

[ Add to Cart ]
```

```text

   ↓
```

```text

   ↓
```

```text
   ↓
```

# Easy Definition for Exam

> **A web application commonly consists of a frontend, backend, and database. The frontend provides the user interface, the backend processes requests and contains business logic, and the database stores application data. The frontend communicates with the backend through APIs, while the backend communicates with the database.**
