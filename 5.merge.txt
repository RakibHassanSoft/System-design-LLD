Merge Conflict

A merge conflict happens in Git when two branches modify the same part of a file differently, and Git cannot decide which change should be kept.

Simple Example

Suppose we have this code:

String name = "Rakib";

Now we create two branches.

Branch 1---

Developer A changes it to:

String name = "Rakib Hassan";

Branch 2----

Developer B changes the same line to:

String name = "Rahim";

Now we try to merge Branch 2 into Branch 1.

Git doesn't know:----

Should I use "Rakib Hassan" or "Rahim"?

So Git creates a merge conflict:----

<<<<<<< HEAD
String name = "Rakib Hassan";
=======
String name = "Rahim";
>>>>>>> branch2
What do these symbols mean?
<<<<<<< HEAD

Means: your current branch's version

=======

Separates the two versions.

>>>>>>> branch2

Means: the version coming from the other branch

How to solve it?------

You manually choose the correct version.

For example, if you want:

String name = "Rakib Hassan";

Delete the conflict markers:

String name = "Rakib Hassan";

Then:

git add .
git commit -m "Resolve merge conflict"
Real-life example

Imagine two students are working on the same project.

Student A:

Login button → Blue

Student B:

Login button → Red

Both changed the same property differently.

Git cannot automatically decide whether the button should be blue or red.

That's a merge conflict.

Easy definition for exam

A merge conflict occurs when Git cannot automatically merge two branches because they have different changes in the same part of a file. The developer must manually choose and resolve the correct changes.
