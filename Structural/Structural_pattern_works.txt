====================Adapter Pattern=================

The Adapter Pattern is used when two parts of a system are incompatible and cannot communicate directly. The adapter works like a translator between them. For example, if your application expects data in one format but an external service provides data in another format, an adapter converts the external data into the format your application understands.

Simple idea: Adapter = Makes incompatible things work together.

Real-life example: A phone charger adapter allows a charger with one type of plug to work with a different type of socket.

Adapter Pattern  Rules-------
Use it when two classes cannot work together because their interfaces are different.
Create an Adapter between them.
The Adapter converts one interface into another.
The original class (Adaptee) does not need to be changed.
The Client works with the expected interface.
Adapter usually wraps the existing class.
Easy to remember:

Different interfaces → Adapter → They can work together.




========================Decorator Pattern======================

The Decorator Pattern is used to add new features or behavior to an existing object without changing its original code. You wrap the original object with another object that adds extra functionality. For example, you may have a basic coffee and then decorate it by adding milk, sugar, or cream.

Simple idea: Decorator = Adds extra features to an existing object.

Real-life example: A basic coffee → add milk → add sugar → add cream. The original coffee does not need to be changed.


Decorator Pattern  Rules------
Use it when you want to add new features/behavior to an object.
Don't change the original class.
Create a Decorator that wraps the object.
The Decorator uses the same interface as the original object.
You can add multiple decorators one after another.
Each decorator adds its own extra behavior.
Easy to remember:

Same object + extra features → Decorator.




=========================== Composite Pattern ==========================

The Composite Pattern is used when you want to treat individual objects and groups of objects in the same way. It is useful for creating tree-like structures. For example, a file system contains files and folders. A file is an individual object, while a folder can contain many files and other folders, but you can perform operations such as open, delete, or move on both files and folders in a similar way.

Simple idea: Composite = Treat individual objects and groups of objects the same way.

Real-life example: A company has employees and departments. You can ask an individual employee or an entire department to perform an operation using the same general approach.

Composite Pattern  Rules ------------
Use it when objects form a tree or hierarchy.
Have a common interface for all objects.
Leaf = single/individual object.
Composite = group that contains other objects.
Composite can contain Leaf and other Composite objects.
Treat single objects and groups in the same way.
Easy to remember:

Single object + Group of objects → Treat them the same.




Simple Comparison
Adapter: Makes incompatible objects work together.
Decorator: Adds features to an existing object.
Composite: Treats individual objects and groups in the same way.
